Welcome

What this course actually is

Software engineering with coding agents: not "typing code," and not "let the AI do it and hope."

  • Manage an agent's context on purpose
  • Extend the agent with skills and MCP servers

Design isn't a separate track here: it's handled the way engineers handle it, by loading the right skill (impeccable, Emil Kowalski's design skill, svg-animations) and judging what comes out.

Foundations

What is Git & GitHub?

  • Git: tracks changes to your code over time, on your own machine
  • GitHub: hosts git repositories online, so people (and agents) can collaborate on them
  • Core idea: a commit is a saved checkpoint you can always get back to
  • Why it matters here: git is the safety net that makes an agent's mistakes reversible
Foundations

Git & GitHub: commands you'll actually use

  • git status: what changed?
  • git add .: stage those changes
  • git commit -m "message": save a checkpoint
  • git push / git pull: sync with GitHub
  • Branch → change → commit → open a pull request → merge

Rule of thumb we'll repeat all course: commit before you let an agent touch anything.

Foundations

How branching & merging works

  • Branching off main lets you work without disturbing it
  • Your commits pile up on that branch while main stays untouched
  • Merging replays your branch's commits back into main in one merge commit
Foundations

Terminal basics

  • pwd: where am I?
  • ls: what's here?
  • cd folder-name: go into a folder (cd .. goes up)
  • mkdir name: make a folder
  • cat file: print a file's contents
  • Environment variables: settings your program reads from outside the code (e.g. secrets, ports)
Foundations

Cloning a project

  • git clone <repo-url>: downloads a full copy of a repo, history included, into a new folder
  • GitHub gives you that URL from the green "Code" button on any repo page
  • cd into the new folder once it's done
  • From there it's a normal local git repo: commit, branch, push, pull, all of it
Foundations

Clone & run this project

  • git clone https://github.com/taxpet06/design-engineering-26f-api.git
  • cd design-engineering-26f-api
  • npm install: downloads its dependencies
  • npm run dev: starts the server locally
  • Open http://localhost:3000 in a browser: same API, running on your machine

In-class activity

Explore, in your team

  • Open the live URL and click around a few endpoints: try /students, /courses/:id/rating, /students/:id/profile
  • Skim the GitHub repo, and read the README to see what each file does
  • Discuss: who would actually use a page built on this data, and what's the one thing they came here to do?
In-class activity

Guidelines for designing your team's page

  • Pick one page of the eventual class website, not the whole site
  • You don't have to use all the data available: pick only what your page actually needs
  • Name the page's one core user flow, start to finish
  • List which API endpoints that flow would call
  • Think through its states: empty, loading, error, too many / too few results
  • Sketch it: paper, Figma, or just words. We'll build with agents in later sessions.

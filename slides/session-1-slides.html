Foundations
4:37–4:39 · 2 minLecture

What is Git & GitHub?

  • Git: tracks changes to your code over time, on your own machine
  • GitHub: hosts git repositories online, so people (and agents) can collaborate on them
  • Core idea: a commit is a saved checkpoint you can always get back to
  • Why it matters here: git is the safety net that makes an agent's mistakes reversible

Git & GitHub: commands you'll actually use

  • git status: what changed?
  • git add .: stage those changes
  • git commit -m "message": save a checkpoint
  • git push / git pull: sync with GitHub
  • Branch → change → commit → open a pull request → merge

Rule of thumb we'll repeat all course: commit before you let an agent touch anything.

Terminal basics

  • pwd: where am I?
  • ls: what's here?
  • cd folder-name: go into a folder (cd .. goes up)
  • mkdir name: make a folder
  • cat file: print a file's contents
  • Tab-complete file and folder names, don't type them out by hand
  • Environment variables: settings your program reads from outside the code (e.g. secrets, ports)
Foundations
4:59–5:02 · 3 minLecture

Cloning a project

  • git clone <repo-url>: downloads a full copy of a repo, history included, into a new folder
  • GitHub gives you that URL from the green "Code" button on any repo page
  • cd into the new folder once it's done
  • From there it's a normal local git repo: commit, branch, push, pull, all of it
